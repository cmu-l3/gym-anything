## GeoPackage Data (v4)

**File**: `data/world_survey.gpkg` (57,344 bytes)
**Format**: Valid GeoPackage (OGC standard), WGS84/EPSG:4326
**Created**: Python stdlib (sqlite3 + struct), no GDAL required
**Extent**: Full world (-180, -90, 180, 90)

### Layer: world_capitals
- **98 records** — real world capital cities with name/country/continent/lon/lat attributes
- Geometry: POINT in GPB format (`GP\x00\x01` + 4-byte SRS + WKB point = 29 bytes)
- QML style: red circle markers (in layer_styles table, `useAsDefault=1`)
- Sample: Tokyo (139.69°E, 35.69°N), Paris, Cairo, Ottawa, Canberra, Bogota, Nairobi...

### Layer: field_observations
- **8 records** — real GBIF biodiversity observations (fetched from GBIF API)
- Fields: observer_name, species, location, obs_date, quality_grade
- Data sourced from 8 countries: USA, Brazil, Australia, Japan, India, Kenya, Germany, South Africa
- QML style: blue square markers (in layer_styles table, `useAsDefault=1`)

### Style Behavior Note
When QField opens a `.gpkg` file directly via Android VIEW intent (without a `.qgs` project file), it does not apply custom QML styles from the `layer_styles` table — it uses its built-in default renderer (red circles for all point layers). Both layers render correctly with labels visible; the visual distinction between layers is via the layer names in the layers panel and the label text (city names vs observer/species names). A `.qgz` project file referencing the GPKG would be needed to apply custom QML styles.

## Known Behaviors

1. **Two-phase tutorial dismissal**: QField shows two distinct tutorials:
   - **App tutorial** (on first launch): Dismissed by monkey-launch warm-up + tap sequence (Next×2 → Skip×2)
   - **Project tutorial** (on first GeoPackage open via VIEW intent): Dismissed by a second VIEW intent warm-up in `setup_qfield.sh`
   Both tutorials are dismissed during post_start so all task start states are clean. If a tutorial still appears in a task, agents can dismiss via the Skip (X) button at actual coords ~(991, 357).

2. **VIEW intent activity**: Use `.QFieldActivity` (not `.QGisActivity` which returns Error type 3).

3. **GeoPackage paths**: QField's file browser shows `files/Imported Datasets/` by default. The VIEW intent works with the root `files/` copy.

4. **Qt app**: QField uses Qt rendering — standard Android `uiautomator dump` only returns the root view. Use manual coordinate-based tapping.

5. **Layer styles**: QField 3.4.6 does not apply GPKG `layer_styles` table QML when opening via direct VIEW intent. Both layers use the default red circle symbol. Task functionality is unaffected since tasks check data state, not visual appearance.

6. **Saved viewport**: QField saves camera position in a sidecar file when a project is closed. Tasks that use a fresh GeoPackage copy (`add_survey_point`, `zoom_to_coordinates`) open at the data extent default; tasks reusing the existing GPKG restore the warm-up camera state (Atlantic view).
