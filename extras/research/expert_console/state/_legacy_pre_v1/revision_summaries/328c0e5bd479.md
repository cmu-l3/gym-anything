The Odoo demo "Chief Technical Officer" and "HR Manager" job records already exist by those names; `upsert_job` returns those existing ids rather than creating duplicates. This is harmless because the verifier compares by id, and the agent finds the position via Odoo's autocomplete by name. But the agent will see ~37 employees in the directory total. The task description names exact full names, so unambiguous selection is still possible.
- **No live verification run**. Per session policy, I did not start the VM/VNC/Odoo container. Syntax-validated all JSON, Python, shell, and embedded Python heredoc bodies. A live `gym-anything run odoo_hr_env --task promotion_and_department_update -i --open-vnc` is recommended before promoting this revision, since the Westmark upserts have not been exercised against a running Odoo 17 instance.
- **Task-only scope**. The expert's feedback ("the data right now is demo data") could in principle be interpreted as an env-level concern. I treated it as task-scoped because (a) it arrived in a task revision session, and (b) other tasks in the same env actively rely on Odoo demo identities (Rachel Perry leave allocation, Doris Cole leave request, etc.) and would break if demo data were excised. If the expert intended an env-wide overhaul, that should be a separate, broader revision.
