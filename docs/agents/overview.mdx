# Agents

The `agents/` folder contains example policies and the programs used to run them.

<Note>
You don't need this part of the repository to use Gym Anything itself.
</Note>

You only need it if:

- you want to run one of the reference policies
- you want a starting point for your own policy
- you want to evaluate a policy across benchmark tasks

## What Lives In `agents/policies/`

`agents/policies/` contains the policy classes.

A policy is the code that looks at the current observation and decides what actions to take next.

We currently ship these policies:

- `ClaudeAgent`
- `Gemini3Agent`
- `Qwen3VLAgent`
- `KimiAzureAgent`

These classes are exported through `agents.policies`, which is why the evaluation commands refer to names such as `--agent ClaudeAgent`.

## What Lives In `agents/evaluation/`

`agents/evaluation/` contains the programs that actually run a policy against environments and tasks.

The two main ones are:

- `run_single.py`: run one agent on one task
- `run_batch.py`: run one agent across many tasks

If you only want to try a policy once, start with `run_single.py`.

## What A Policy Receives

Our current policy interface is built around four methods:

- `__init__`
- `init(task_description, display_resolution, save_path)`
- `step(obs, action_outputs)`
- `finish(...)`

The important one is `step(...)`.

That method receives:

- the latest observation from the environment
- the outputs from the previous actions

and it returns one or more action groups.

Each action group contains:

- `tool_id`
- `actions`

The `actions` list can contain normal environment actions such as mouse and keyboard input. It can also contain built-in control actions such as:

- `{"action": "screenshot"}`
- `{"action": "wait", "time": 1.5}`

Those control actions are handled by the environment layer, not by the evaluation loop.

## The Fastest Way To Try One

If you want to try one of the shipped policies, use `run_single`:

```bash
python -m agents.evaluation.run_single \
  --env_dir benchmarks/cua_world/environments/zotero_env \
  --task create_saved_search \
  --agent ClaudeAgent \
  --agent_args '{"model":"claude-opus-4","exp_name":"demo"}'
```

That command:

- loads the environment
- resets it
- creates the agent
- lets the agent act until the run finishes
- writes run artifacts

## If You Want To Add Your Own Policy

The simplest workflow is:

1. copy a nearby file in `agents/policies/`
2. implement the same basic methods
3. export the new class from `agents/policies/__init__.py`
4. run it with `agents.evaluation.run_single`

If you're starting from scratch, read:

1. `agents/policies/base.py`
2. one concrete policy such as `agents/policies/claude.py`
3. `agents/evaluation/run_single.py`

That gives you the policy interface first, then one implementation, then the program that drives it.
