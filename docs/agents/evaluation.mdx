# Evaluation

The evaluation programs are the part of `agents/` that actually runs policies against environments.

There are two main entry points:

- `agents.evaluation.run_single`
- `agents.evaluation.run_batch`

## `run_single`: One Agent, One Task

Use `run_single` when you want to run one policy on one task.

Example:

```bash
python -m agents.evaluation.run_single \
  --env_dir benchmarks/cua_world/environments/zotero_env \
  --task create_saved_search \
  --agent ClaudeAgent \
  --agent_args '{"model":"claude-opus-4","exp_name":"demo"}'
```

The important arguments are:

- `--env_dir`: path to the environment folder
- `--task`: task id inside that environment
- `--agent`: policy class name from `agents.policies`
- `--agent_args`: JSON string passed into the policy

Common optional arguments are:

- `--steps`: maximum number of agent steps
- `--use_cache`
- `--cache_level`
- `--use_savevm`

`--agent_args` is policy-specific. In our reference policies, it often includes keys such as `model` and `exp_name`.

## What `run_single` Does

At a high level, `run_single` does this:

1. load the environment and selected task
2. reset the environment
3. create the policy class you selected
4. call `agent.init(...)`
5. capture an observation
6. repeat:
   - call `agent.step(obs, action_outputs)`
   - send the returned actions to the environment
   - feed the action results back into the policy
7. finish the task with `mark_done=True`
8. close the environment
9. call `agent.finish(...)`

If you're trying to understand how the loop works, `agents/evaluation/run_single.py` is the file to read.

## `run_batch`: One Agent, Many Tasks

Use `run_batch` when you want to run one policy across a list of tasks.

Example:

```bash
python -m agents.evaluation.run_batch \
  --agent ClaudeAgent \
  --model claude-opus-4 \
  --env_dir zotero \
  --split test \
  --max_tasks 5
```

`run_batch` builds a list of `(task, environment)` pairs and then launches `run_single` once for each one.

## What `run_batch` Selects

The main arguments that decide what gets run are:

- `--env_dir`: one environment key, one environment path, or `all`
- `--split`: task list name such as `train`, `test`, or `all`
- `--surface`: `raw` or `verified`
- `--max_tasks`: limit how many tasks to run
- `--repeat`: repeat the whole batch more than once

<Tip>
If you're only trying to verify that a policy works at all, start with `run_single` before using `run_batch`.
</Tip>

## If You Want To Change The Loop

Read the evaluation files in this order:

1. `agents/evaluation/run_single.py`
2. `agents/evaluation/run_batch.py`
3. `agents/evaluation/setup.py`

`run_single.py` is the main loop. `run_batch.py` is mostly task selection plus repeated calls into `run_single`.
